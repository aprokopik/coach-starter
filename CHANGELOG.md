# Changelog

One version number for this coach, MAJOR.MINOR.PATCH, held in `VERSION`. MAJOR: a contract changes (`coach/engine/RULES.md`, `coach/engine/schemas.json`, a coach.json row shape, a store collection the morning run reads). MINOR: a new feature. PATCH: a fix. `setup/update.py` brings a coach made from an older kit up to the latest one.

## 5.1.0 (2026-11-08)
- Package: updates for testers who already set up (the kit maker asked Nov 8 how to push updates to them; signed off "Yes, build it"). The kit now records which files are its own (`setup/kit-manifest.json`) and setup fingerprints them as installed (`setup/installed.json`). `setup/update.py` brings a coach from an older kit up to a newer one: kit files replaced, locally edited ones kept with the newer copy set aside for a hand merge, the athlete's profile, state, log, plans and data never touched; `setup/personalize.py --refresh` then re-applies names, links, time zone, schedules and feeds and adds sections the engine now reads (an empty Persona in PROFILE.md and Push contract in CURRENT-STATE.md, which TEAM.md refers to). Testers paste `UPDATE-PROMPT.md` into Claude Code. The kit's CHANGELOG now carries the shared changes since 4.1.0 as the testers' "what's new". New coaches' morning task reads its prompt from the repo instead of a pasted copy. Fix: a second personalize run no longer adds the Strava feed twice. the kit maker's own coach is unchanged.

## 5.0.0 (2026-11-08)
- Contract: `coach/engine/RULES.md` reading order now points to `coach/engine/TEAM.md` (the kit maker said yes on the card, Nov 8), so every check-in and review applies the support team lenses in TEAM.md's order. MAJOR because RULES.md changed.

## 4.5.0 (2026-11-08)
- Changes to the original athlete's own coaching only; nothing in the shared engine.

## 4.4.1 (2026-11-07)
- Package: the kit ships every workflow with no schedule; `setup/personalize.py` adds the athlete's local Garmin (or Strava) schedule at onboarding. The coach-starter template repository ran the shipped 4-a-day Garmin pull with no login and failed every run from Nov 6 (the kit maker forwarded the failure email Nov 7), committing a status file each time; a fresh tester copy had the same failure until its secrets were added. `test_kit.py` now refuses any shipped `cron:`. the kit maker's own coach is unchanged.

## 4.4.0 (2026-11-07)
- Races: #50 race start times on the event (the kit maker: "Race start times should be listed in the event"): `start_time`, `start_basis` (posted or expected), `start_note` in races.json, required once registered or planned and posted by 21 days out (race_template, race_check); shown in the race-week banner, race details, Season list, Roadmap and the shared Race Season page; in the morning facts so the check-in names it in race week; the weekly race watch fills and verifies it.

## 4.3.0 (2026-11-07)
- Package: guided install and a feedback loop (the kit maker asked Nov 6 that testers' own Claude walk them through the whole setup, troubleshoot with them, and send issues back; they chose both an issue link and a text fallback). New `SETUP-PROMPT.md` guides Part 1 step by step in a claude.ai chat from screenshots and hands its setup notes to the onboarding session. `ONBOARDING-PROMPT.md` keeps `setup/SETUP-LOG.md` through Stage 2 and ends with four feedback questions; the shipped `CLAUDE.md` keeps logging setup or coach problems afterwards. `setup/feedback.py` refuses a log with health data, secrets or emails, then prints a prefilled `kit-feedback` issue link on the kit's home repository (`setup/kit.json`) and a copy-ready text block. `kit/README.md` lists how findings go into the Improvements log. the kit maker's own coach is unchanged.

## 4.2.0 (2026-11-07)
- Data feeds: athletes without Garmin (the kit maker asked Nov 5 for Oura, Ultrahuman, Apple Watch and Strava testers). An iPhone Shortcut sends sleep, HRV, resting HR, steps and weight from Apple Health (`ingest-apple-health.yml`, `scripts/apple_health.py`, guide `coach/ops/APPLE-HEALTH-SHORTCUT.md`); workouts come from Strava (`pull-strava.yml`, `scripts/pull_strava.py`, one-time `scripts/setup_strava.py`), since a Shortcut cannot read workouts. Both write the Garmin pull's own columns, so every coach tool reads them unchanged. `morning_facts.py` freshness names the source and drops Body Battery from the core list for these athletes. The kit asks which device at onboarding and sets the schedules and data paths to match. the kit maker's own coach is unchanged (the new workflows have no schedule here).
- Package: testers start from a private `coach-starter` template repository (Use this template) instead of uploading the zip, after the first alpha tester hit GitHub's 100-files-per-upload limit (Nov 6, the kit maker chose the template). INSTALL keeps a three-drop upload as the fallback, and because the web upload refuses the hidden `.github` folder, the kit carries a visible copy in `setup/workflows` that `setup/personalize.py` restores.

## 4.1.0 (2026-11-07)
- Package: starter kit for a new athlete (the kit maker asked Nov 5; made a standing, versioned deliverable on their sign-off the same day). `kit/build_kit.py` builds `dist/coach-starter-kit-<VERSION>.zip` from this repo: the engine, tools, dashboard and workflows, with every personal file swapped for a blank template and names, links and task ids scrubbed; it refuses to finish if a private term survives. New athletes follow `START-HERE.md`, `INSTALL.md` (GitHub and Garmin, browser only) and `ONBOARDING-PROMPT.md` (a one-question-at-a-time interview in Claude, then `setup/personalize.py` writes their profile, screen, races, zones, fitness layout and pull schedule, and Claude creates the dashboard and scheduled tasks). `coach/tests/test_kit.py` builds, personalizes and runs the kit for a made-up athlete. Each release now also gets its kit: `release-tag.yml` gains a `kit` job that builds the zip from the tagged commit and attaches it to the GitHub Release. Nothing in the live coach changes.
